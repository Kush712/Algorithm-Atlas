Problem of the Day

Predict the Winner
LeetCode #486

Two players. One array. Each picks from the ends.
Can Player 1 guarantee a win? Let's break it down with Game Theory.

⚡ Medium 🎯 Dynamic Programming 🧠 Game Theory 🔄 Recursion 🎮 Minimax
01 — The Problem
📖
What's the Problem?

You're given an array of integers. Two players take turns picking a number from either the left end or the right end of the remaining array. Player 1 always goes first. Both players play optimally — meaning they'll always make the best possible move. Return true if Player 1 can win or tie, otherwise false.

💡
Key insight: Both players are equally smart! The opponent will always pick the option that leaves you with the worst possible outcome. This is the core of the Minimax strategy.

03 — Intuition
🧠
Why Minimax?

Think of it like a chess match — when it's your turn, you pick the maximum score you can get. When it's the opponent's turn, they'll try to minimize your future score, so from your perspective the outcome is the minimum.


The recursion models this perfectly:

  • Pick left (nums[i]): You gain that value, but then the opponent plays optimally from the remaining subarray. The opponent picks the best for themselves, leaving you the min of two branches.
  • Pick right (nums[j]): Same logic — you gain that value, opponent minimizes your remaining gain.
  • You take the max of both choices because you play optimally too!
⚠️
Why min() inside and max() outside?
After you pick, the opponent picks next (they maximize for themselves = minimize for you). So from your perspective, you get the minimum of the two remaining options — then you choose whichever starting pick gives you the maximum overall.
04 — Approach
🗺️
Step-by-Step Approach

1. Define the recursive function solve(i, j)

It returns the maximum score the current player (Player 1) can collect from the subarray nums[i..j].

2. Base cases

If i > j → no elements left → return 0.
If i == j → only one element → return nums[i].

3. Explore both choices

Pick left: gain nums[i] + min(solve(i+2,j), solve(i+1,j-1))
Pick right: gain nums[j] + min(solve(i,j-2), solve(i+1,j-1))

4. Compare Player 1's score to the total

If player1_score ≥ total − player1_score, Player 1 wins or ties!

⚙️
Key Functions Explained
Function Purpose
solve(i, j, nums) Recursively finds the max score Player 1 can get from subarray nums[i..j]. This is the heart of the Minimax logic.
PredictTheWinner(nums) Driver function — computes total sum, calls solve() for Player 1's best score, then checks if P1 ≥ P2.
min(a, b) Used to simulate the opponent's optimal play — they leave you the worst option.
max(a, b) Used by the current player to choose the best of two picks (left vs right).
07 — Patterns Used
🧩
Design Patterns
🎮 Minimax Game Theory
🔄 Recursion
📦 Interval DP (i, j)
🧪 Optimal Substructure
✂️ Two-End Picking
  • Minimax: You maximize your gain; the opponent minimizes it. Classic two-player game pattern.
  • Interval DP (i, j): The subproblem is defined by a contiguous subarray from index i to j. This shrinks as picks happen.
  • Two-End Picking: Players can only pick from the left or right end — this constrains the search space elegantly.
  • Optimal Substructure: The optimal solution for solve(i,j) depends on optimal solutions of smaller subproblems.
08 — Full Code
C++ • solution.cpp 
// leetcode problem 486 Predict the Winner
// https://leetcode.com/problems/predict-the-winner/
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int solve(int i, int j, vector<int>& nums) {
        if(i > j) {                     // no elements left
            return 0;
        } else if(i == j) {             // only one element
            return nums[i];
        }
        // Pick left: nums[i], opponent plays optimally
        int pick_i = nums[i] + min(solve(i+2,j,nums), solve(i+1,j-1,nums));
        // Pick right: nums[j], opponent plays optimally
        int pick_j = nums[j] + min(solve(i,j-2,nums), solve(i+1,j-1,nums));
        return max(pick_i, pick_j);      // best of both picks
    }

    bool PredictTheWinner(vector<int>& nums) {
        int n = nums.size();
        int total = 0;
        for(int i = 0; i < n; i++) {
            total += nums[i];
        }

        int player_1 = solve(0, n-1, nums);
        int player_2 = total - player_1;
        return player_1 >= player_2;
    }
};

int main() {
    Solution solution;
    vector<int> nums = {1, 5, 2};
    bool result = solution.PredictTheWinner(nums);
    cout << (result ? "Player 1 wins." : "Player 2 wins.") << endl;

    vector<int> nums2 = {1, 5, 233, 7};
    bool result2 = solution.PredictTheWinner(nums2);
    cout << (result2 ? "Player 1 wins." : "Player 2 wins.") << endl;

    vector<int> nums3 = {1, 5, 2, 4};
    bool result3 = solution.PredictTheWinner(nums3);
    cout << (result3 ? "Player 1 wins." : "Player 2 wins.") << endl;

    return 0;
}

10 — Complexity Analysis
📊
Time & Space Complexity
Time
O(2ⁿ)
Each call branches into 2 sub-calls.
No memoization = exponential.
Space
O(n)
Max recursion depth = n levels
(the array length).
🚀
Want to optimize? Add memoization with a 2D table dp[i][j] to cache results of solve(i, j). This brings it down to O(n²) time and space — a massive improvement!
11 — Key Takeaways
✅
Remember These
  • Minimax = you maximize, opponent minimizes. Classic game theory.
  • The min() inside represents the opponent being smart — they'll pick the worse option for you.
  • Subproblem is defined by an interval [i, j] — shrinks from both ends.
  • Player 1's total is computed by solve(); Player 2 gets total − P1.
  • This pure recursive solution is O(2ⁿ) — add memoization for O(n²).
  • This pattern appears in many game theory problems: Stone Game, Coins in a Line, etc.
