01 The Problem
📖
What's the Problem?

Alice and Bob take turns picking stones from a row. On each turn, a player can take 1, 2, or 3 stones from the front of the remaining row. The stone values can be negative! Alice goes first. The player with the higher total score wins.


Return "Alice" if Alice wins, "Bob" if Bob wins, or "Tie" if they tie.

04 Intuition
🧠
The Relative Score Trick

Instead of tracking Alice's and Bob's scores separately, we define:


🎯
solve(i) = the maximum score advantage the current player can achieve starting from index i

The magic formula:

  • Take 1 stone: stone[i] − solve(i+1)
  • Take 2 stones: stone[i] + stone[i+1] − solve(i+2)
  • Take 3 stones: stone[i] + stone[i+1] + stone[i+2] − solve(i+3)
  • Choose the max of all valid options!
🔑
Why subtract solve(i+k)?
After you take stones, the opponent plays optimally from the remaining position. Their best advantage becomes your disadvantage. So we subtract: my gain − opponent's best advantage. If the result is positive → I'm winning. Negative → opponent is winning.
05 Approach
🗺️
Step-by-Step Approach

1. Define solve(i) — relative advantage

Returns how much better the current player does than their opponent from index i onward. Positive = current player leads.

2. Base case

If i ≥ n → no stones left → return 0. If already memoized in t[i], return cached result.

3. Try taking 1, 2, or 3 stones

Take 1: stone[i] − solve(i+1)
Take 2: stone[i]+stone[i+1] − solve(i+2)
Take 3: stone[i]+stone[i+1]+stone[i+2] − solve(i+3)
Store the max in t[i].

4. Interpret the final result

result > 0 → "Alice" wins
result < 0 → "Bob" wins
result == 0 → "Tie"

07 Methods & Functions

Key Functions Explained
Function Purpose
solve(stone, i) Recursively finds the relative score advantage of the current player from index i onward. Uses t[i] memoization.
stoneGameIII(stone) Driver function — initializes memo table, calls solve(stone, 0), then maps the result to "Alice", "Bob", or "Tie".

max(a, b) The current player picks whichever option (take 1, 2, or 3) gives the highest advantage.
08 Patterns Used
🧩
Design Patterns
🎮 Minimax via Relative Score
🔄 Recursion + Memoization
📦 1D DP on Index
🧪 Optimal Substructure
🎲 Variable-Width Picks
  • Relative Score Minimax: Instead of two separate scores, track the difference. Your gain minus opponent's best = your advantage. Elegant and 1D!
  • Variable-Width Picks: Unlike classic games where you pick 1, here you can pick 1, 2, or 3 — creating a 3-way branching recursion.
  • 1D DP: State is just the starting index i. Much simpler than 2D interval DP!
  • Subtraction = Opponent's Turn: The minus in the formula naturally models turn-switching without explicit player tracking.
09 Full Code
C++ • solution.cpp 
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    vector<int> t;                       // memoization table

    int solve(vector<int>& stone, int i) {
        int n = stone.size();
        if(i >= n) {                     // no stones left
            return 0;
        }
        if(t[i] != -1) {                  // already computed
            return t[i];
        }

        // Take 1 stone
        int result = stone[i] - solve(stone, i + 1);

        // Take 2 stones (if possible)
        if(i + 1 < n) {
            result = max(result,
                stone[i] + stone[i+1] - solve(stone, i + 2));
        }

        // Take 3 stones (if possible)
        if(i + 2 < n) {
            result = max(result,
                stone[i] + stone[i+1] + stone[i+2] - solve(stone, i + 3));
        }

        return t[i] = result;             // cache & return
    }

    string stoneGameIII(vector<int>& stone) {
        int n = stone.size();
        t.resize(n + 1, -1);             // init memo
        int result = solve(stone, 0);

        if(result < 0)       return "Bob";
        else if(result > 0) return "Alice";
        else                 return "Tie";
    }
};

int main() {
    Solution solution;

    vector<int> stone = {1, 2, 3, 7};
    cout << solution.stoneGameIII(stone) << endl;   // "Bob"

    vector<int> stone3 = {1, 2, 3};
    cout << solution.stoneGameIII(stone3) << endl;  // "Tie"

    vector<int> stone2 = {1, 2, 3, -9};
    cout << solution.stoneGameIII(stone2) << endl;  // "Alice"
    return 0;
}

11 Complexity Analysis
📊
Time & Space Complexity
Time
O(n)
n unique states, each doing
O(1) work (max of 3 options).
Space
O(n)
1D memoization vector of size n
+ O(n) recursion stack.
🚀
Why O(n) and not O(3ⁿ)? Without memoization, the recursion branches 3 ways at each level — exponential! But with the t[i] cache, each of the n states is computed exactly once. The memoization brings it down from exponential to linear — a massive win!
12 Key Takeaways
✅
Remember These
  • Relative score trick: my_gain − solve(next) elegantly handles turn-switching without tracking whose turn it is.
  • The subtraction models the opponent playing optimally — what they gain becomes your loss.
  • Negative values make this problem much harder than Stone Game I — greedy fails!
  • State is just index i — 1D DP, since we always pick from the front.
  • Three possible outcomes: "Alice", "Bob", or "Tie".
  • Memoization drops time from O(3ⁿ) to O(n) — always memoize overlapping subproblems!
  • This "relative advantage" pattern works for all variable-pick game problems (Stone Game IV, V, etc.).
