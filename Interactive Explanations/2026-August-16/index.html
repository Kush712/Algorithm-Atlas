Stone Game IXLeetCode #2029

Alice and Bob play a turn-based game picking stones. The sum of picked stones must not be a multiple of 3. Return true if Alice wins.

🟡 Medium🎮 Game Theory📐 Math🔢 Modulo Arithmetic
01 The Problem
📖
What's the Problem?

You have an array of stones. Alice and Bob take turns picking a stone and adding its value to a running sum. The player who makes the running sum a multiple of 3 loses.


Alice plays first. If there are no stones left, Alice loses. Does Alice have a winning strategy?

💡
Key Insight: The actual values of the stones don't matter, only their values modulo 3. We can reduce the array to a count of 0s, 1s, and 2s!

03 Intuition
🧠
Math over Simulation
  • Picking a 0 flips the turn without changing the sum mod 3. It's just a delay tactic!
  • If Alice starts with a 1, the sequence of valid picks must be: 1, 1, 2, 1, 2, 1, 2...
  • If Alice starts with a 2, the sequence must be: 2, 2, 1, 2, 1, 2, 1...
  • Thus, if count of 0s is even, Alice can win if there's at least one 1 and one 2 (so she can choose the winning path).
  • If count of 0s is odd, the turn order flips, and Alice needs a difference of > 2 between count of 1s and 2s to win.
04 Approach
🗺️
Step-by-Step Approach

1. Count Modulo Frequencies

Create an array `cnt` of size 3 to store the count of numbers that are 0, 1, and 2 mod 3.

2. Check Even 0s

If `cnt[0]` is even, Bob can always neutralize Alice's 0s. Alice wins if she has both 1s and 2s to choose from.

3. Check Odd 0s

If `cnt[0]` is odd, Alice needs an overwhelming majority of 1s or 2s (difference > 2) to force Bob into a losing move.

06 Patterns Used
🧩
Design Patterns
🎮 Game Theory
🔢 Modulo Bucketing
📊 Frequency Counting
  • Modulo Bucketing: Reduce large numbers to a small finite set of states (0, 1, 2) when the goal involves divisibility.
  • Game Theory (Nim-like): Instead of minimax simulation, find mathematical win conditions based on parity (even/odd).
07 Full Code
C++ • solution.cpp
class Solution {
public:
    bool stoneGameIX(vector<int>& stones) {
        int cnt[3] = {0, 0, 0};
        for (int s : stones) {
            cnt[s % 3]++;
        }

        if (cnt[0] % 2 == 0) {
            return cnt[1] > 0 && cnt[2] > 0;
        }

        return abs(cnt[1] - cnt[2]) > 2;
    }
};

10 Key Takeaways
✅
Remember These
  • Game Theory problems often have O(1) space, O(N) time math solutions. Look for patterns before writing minimax!
  • When dealing with divisibility, always bucket by modulo.
  • Zero elements are often just "turn flippers" — analyze their parity (even/odd).
