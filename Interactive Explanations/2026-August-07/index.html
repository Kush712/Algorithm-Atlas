01 The Problem
📖
What's the Problem?

Given a number as a string num (can be very large!) and a target t, find the smallest number ≥ num whose digit product is divisible by t.


This is the hard version of LC 3345. The key difference: num can have up to 10⁵ digits — far too large to iterate number by number. We need a clever approach!

🔥
Critical constraint: Since t must be expressible purely in terms of primes 2, 3, 5, 7 (the only primes that are digits), if t has any other prime factor, it's impossible → return "-1".

03 Intuition
🧠
Three-Phase Strategy

The algorithm combines greedy scanning, backtracking, and digit filling:

  • Phase 1 — Prime check: Divide t by 2, 3, 5, 7 until nothing's left. If temp ≠ 1, then t has a non-digit prime factor → return "-1".
  • Phase 2 — Prefix scan: Track remainingFactor[i] — how much of t is still not covered after processing digits 0..i. Use GCD to divide out what each digit contributes.
  • Phase 3 — Backtrack: Starting from the rightmost digit (or the first 0), try incrementing it. For each candidate digit, check if the remaining slots can be filled with digits 9→2 to cover the remaining factor.
  • Phase 4 — Fill slots: freeSlotsFiller greedily packs the largest digits (9, 8, 7...) first to minimize the number, pad with 1s if extra slots remain.
💡
Why GCD? When we encounter digit d, it contributes gcd(remaining, d) to the target. We divide out only the common factors, not the full digit, because we need the exact remaining obligation.
04 Approach
🗺️
Step-by-Step Approach

1. Verify t is achievable

Strip all factors of 2, 3, 5, 7 from t. If anything remains, no single digit can contribute it → return "-1".

2. Compute prefix remaining factors

For each position i, compute how much of t is still needed: remainingFactor[i+1] = remainingFactor[i] / gcd(remainingFactor[i], digit). Stop at any 0 digit (product becomes 0).

3. Check: already valid?

If remainingFactor[n] == 1, the number itself works — return it!

4. Backtrack from right

Start from the first 0 position (or the last digit). Try incrementing the digit and check if the remaining free slots can satisfy the remaining factor using freeSlotsFiller.

5. Last resort: add a digit

If no position works, create a number with n+1 digits filled entirely by freeSlotsFiller(t, n+1).

06 Patterns Used
🧩
Design Patterns

🔙 Backtracking

📊 Prefix Arrays
  • Greedy Construction: freeSlotsFiller always picks the largest digit first (9, 8, 7...) to pack max factor contribution into fewer digits, leaving the rest as 1s → smallest number.
  • Backtracking: When the current prefix doesn't work, backtrack to the nearest modifiable position and try a larger digit.
  • GCD Trick: Instead of tracking full prime decomposition, use gcd(remaining, digit) to compute exactly how much each digit "pays off".
  • Prefix Factor Array: Precompute the remaining obligation at each position — avoids recomputation during backtracking.
07 Full Code
C++ • solution.cpp 
class Solution {
public:
    typedef long long ll;

    ll gcd(ll a, ll b) {
        while (b != 0) {
            ll temp = b;
            b = a % b;
            a = temp;
        }
        return a;
    }

    string freeSlotsFiller(ll required, int length) {
        string str;
        for (int digit = 9; digit >= 2; digit--) {
            while (required % digit == 0) {
                str.push_back(digit + '0');
                required /= digit;
            }
        }
        if (required != 1) return "";    // impossible
        while (str.length() < length)
            str.push_back('1');        // pad with 1s
        if (str.length() > length) return "";
        reverse(str.begin(), str.end());
        return str;
    }

    string smallestNumber(string num, ll t) {
        int n = num.length();

        // Phase 1: Check if t is achievable
        ll temp = t;
        for (int p : {2,3,5,7})
            while (temp % p == 0) temp /= p;
        if (temp != 1) return "-1";

        // Phase 2: Prefix remaining factors
        vector<ll> rf(n+1, t);
        for (int i = 0; i < n; i++) {
            int d = num[i] - '0';
            if (d == 0) break;
            rf[i+1] = rf[i] / gcd(rf[i], (ll)d);
        }
        if (rf[n] == 1) return num;     // already valid!

        // Phase 3: Backtrack
        int zeroIdx = (num.find('0') == string::npos)
                     ? n-1 : num.find('0');
        for (int i = zeroIdx; i >= 0; i--) {
            ll req = rf[i];
            int free = n - 1 - i;
            for (int d = max(num[i]-'0'+1,1); d <= 9; d++) {
                ll fr = req / gcd(req, (ll)d);
                string fill = freeSlotsFiller(fr, free);
                if (!fill.empty() ||
                    (free==0 && fr==1))
                    return num.substr(0,i)
                        + char(d+'0') + fill;
            }
        }
        return freeSlotsFiller(t, n+1);  // add digit
    }
};

10 Key Takeaways
✅
Remember These
  • Only primes 2, 3, 5, 7 can appear as digit factors. Any other prime in t makes the problem impossible.
  • GCD is the elegant tool to track how much of the target each digit "pays off".
  • Greedy digit filling (9→2) packs maximum factor contribution into minimum digits → smallest number.
  • The prefix remaining factor array avoids recomputation and enables efficient backtracking.
  • Finding the first 0 is crucial — any digit product involving 0 is 0 (divisible by everything but kills the chain).
  • This is a masterclass in combining number theory + greedy + backtracking for large-number problems.
