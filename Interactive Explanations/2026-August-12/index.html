Merge overlapping occupied intervals, then remove a free interval range. Return the remaining occupied segments in sorted order.

🟡 Medium 📊 Intervals 🔀 Sorting 🤝 Merge ✂️ Split & Filter
01 The Problem
📖
What's the Problem?

Given a list of occupiedIntervals and a free range [freeStart, freeEnd]:

  • Merge all overlapping or touching occupied intervals.
  • Remove all integer points within the free range from the merged intervals.
  • Return the remaining intervals in sorted order.
💡
Classic interval problem: Merge first, then filter. Two intervals touch if one starts immediately after the other ends (e.g., [1,1] and [2,2] merge to [1,2]).

03 Intuition
🧠
Two-Phase Approach

This problem is solved in two clean phases:

  • Phase 1 — Merge: Sort intervals by start, then greedily merge overlapping/touching ones.
  • Phase 2 — Filter: For each merged interval, check overlap with [freeStart, freeEnd]. Split or truncate as needed.
⚠️
Watch for touching intervals: [1,3] and [4,5] should merge into [1,5] because they're adjacent. Use start ≤ prev_end + 1 for the merge condition.
04 Approach
🗺️
Step-by-Step Approach

1. Sort intervals by start time

Sorting ensures we process intervals left-to-right, making merging trivial.

2. Merge overlapping/touching intervals

If current.start ≤ prev.end + 1, extend the previous interval. Otherwise start a new one.

3. Filter against the free range

For each merged interval, check: fully before free? fully after? partial overlap? Split accordingly.

4. Collect remaining segments

Build the result array from the surviving (possibly split) intervals.

  • Interval Merge: The classic sort-then-merge pattern — appears in meeting rooms, calendar, and scheduling problems.
  • Interval Split: When a range "cuts" an interval, you may produce 0, 1, or 2 output intervals.
  • Greedy Sweep: Process intervals left-to-right after sorting — no need for complex data structures.
07 Full Code
C++ • solution.cpp
class Solution {
public:
    vector<vector<int>> filterIntervals(
        vector<vector<int>>& occ,
        int fs, int fe) {

        sort(occ.begin(), occ.end());

        // Phase 1: Merge
        vector<vector<int>> merged;
        for (auto& iv : occ) {
            if (!merged.empty() &&
                iv[0] <= merged.back()[1] + 1)
                merged.back()[1] =
                    max(merged.back()[1], iv[1]);
            else
                merged.push_back(iv);
        }

        // Phase 2: Filter
        vector<vector<int>> result;
        for (auto& iv : merged) {
            if (iv[1] < fs || iv[0] > fe)
                result.push_back(iv);
            else {
                if (iv[0] < fs)
                    result.push_back({iv[0], fs-1});
                if (iv[1] > fe)
                    result.push_back({fe+1, iv[1]});
            }
        }
        return result;
    }
};

10 Key Takeaways
✅
Remember These
  • Sort first — almost every interval problem starts with sorting by start time.
  • Touching intervals ([1,3] and [4,5]) should merge if the problem defines them as adjacent.
  • When a range cuts an interval, consider three cases: no overlap, partial left, partial right.
  • This merge + filter pattern appears in meeting rooms, calendar booking, and resource scheduling.
  • Always check edge cases: empty intervals, free range covering everything, single-point intervals.
