Problem of the Day

Stone Game II LeetCode #1140

Alice and Bob take turns picking 1 to 2M piles from the front.
Both play optimally. How many stones can Alice guarantee?

⚡ Medium 🎯 Dynamic Programming 🧠 Game Theory 🎮 Minimax 📦 Memoization
🧑 Alice (Maximize) 🤖 Bob (Minimize)
01 The Problem
📖
What's the Problem?

You have n piles of stones arranged in a row. Alice and Bob take turns (Alice goes first). On each turn, the current player takes the first x piles where 1 ≤ x ≤ 2M. After taking x piles, M becomes max(M, x). Return the maximum stones Alice can get when both play optimally.

🎮
The M parameter is key: M starts at 1, so initially you can take 1 or 2 piles. But if you take x piles, M becomes max(M, x) — potentially expanding the range for the next player. This creates a fascinating trade-off: take more now (more stones) but give the opponent a wider range!

03 Intuition
🧠
Minimax with Variable Range

This is a classic minimax game, but with a twist — the number of piles you can take grows dynamically:

  • Alice (person=1): Wants to maximize her total. She tries all possible x (1..2M), takes the sum of those piles, and adds the recursive result.
  • Bob (person=0): Wants to minimize Alice's total. He tries all x and picks the one that gives Alice the least.
  • State: (person, i, M) — who's playing, current pile index, current M value.
  • Memoization: There are only 2 × n × n unique states — cache them in t[person][i][m].
💡
Why doesn't Bob track his own score? The function solveForAlice always returns Alice's score. When it's Bob's turn, he picks the move that minimizes Alice's total — no need to track Bob's score separately!
04 Approach
🗺️
Step-by-Step Approach

1. Define state: solve(person, i, M)

Returns Alice's optimal score from position i onward, with current M, when it's person's turn (1=Alice, 0=Bob).

2. Base case: i ≥ n

No piles left → return 0 (no more stones for Alice).

3. Try all x from 1 to min(2M, n-i)

For each x, accumulate the sum of piles[i..i+x-1]. If Alice: max(stone + recurse). If Bob: min(recurse) — Bob doesn't add stones (we only track Alice).

4. Update M = max(M, x)

After taking x piles, the range expands for the next player if x > M.

5. Memoize in t[person][i][m]

Cache the result to avoid recomputation — each state is visited at most once.

06 Patterns Used
🧩
Design Patterns
🎮 Minimax
📦 Memoization
🎯 Game DP
📐 Variable Range
🔄 Recursion
  • Minimax: Alice maximizes, Bob minimizes — classic two-player game theory. The function alternates perspective.
  • 3D Memoization: State is (person, i, M). Without memo, this would be exponential. With memo, each state is O(n) to compute.
  • Variable Range DP: Unlike fixed-range games (pick 1 or 2), here the range grows with M — making the state space more complex.
07 Full Code
C++ • solution.cpp 
class Solution {
public:
    int t[2][101][101];           // memo: [person][i][m]

    int solveForAlice(vector<int>& piles,
            int person, int i, int m) {
        int n = piles.size();
        if (i >= n) return 0;        // no piles left

        int stone = 0;
        int result = (person == 1)
                   ? -1 : INT_MAX;  // Alice→max, Bob→min

        if (t[person][i][m] != -1)
            return t[person][i][m];    // cached!

        for (int x = 1; x <= min(2*m, n-i); x++) {
            stone += piles[i+x-1];    // accumulate piles

            if (person == 1) {         // Alice: maximize
                result = max(result,
                    stone + solveForAlice(
                        piles, 0, i+x,
                        max(m, x)));
            } else {                  // Bob: minimize Alice
                result = min(result,
                    solveForAlice(
                        piles, 1, i+x,
                        max(m, x)));
            }
        }
        return t[person][i][m] = result;
    }

    int stoneGameII(vector<int>& piles) {
        memset(t, -1, sizeof(t));
        return solveForAlice(piles, 1, 0, 1);
    }
};

09 Complexity Analysis
📊
Time & Space Complexity
Time
O(n³)
2 × n × n states,
each tries up to 2M ≈ n moves.
Space
O(n²)
Memo table t[2][n][n]
+ O(n) recursion stack.
🚀
n ≤ 100: With n³ ≈ 10⁶, this runs comfortably within time limits. The memoization reduces the exponential recursion tree to a polynomial number of unique states.
10 Key Takeaways
✅
Remember These
  • Minimax + Memoization is the go-to pattern for two-player optimal games.
  • The function tracks Alice's score only — Bob's turn minimizes it, no separate tracking needed.
  • M = max(M, x) creates a dynamic range — the key twist that makes this harder than basic Stone Game.
  • 3D state space (person, i, M) — don't forget the person dimension!
  • Initialize result to -1 for maximizer, INT_MAX for minimizer — classic minimax setup.
  • This pattern extends to Stone Game III, IV, V and other variable-pick games.
