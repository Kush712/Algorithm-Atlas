Problem of the Day

Stone Game
LeetCode #877

Alice and Bob play a game with piles of stones. Alice always goes first.
Can she always win? Let's prove it with Game Theory + Memoization.

⚡ Medium 🎯 Dynamic Programming 🧠 Game Theory 🔄 Recursion 🎮 Minimax
01 — The Problem
📖
What's the Problem?

Alice and Bob play a game with an even number of stone piles arranged in a row. Each pile has a positive integer number of stones piles[i]. The total number of stones across all piles is odd, so there are no ties.


Players take turns, with Alice going first. Each turn, a player picks the first or the last pile from the remaining row. The player with the most stones wins. Return true if Alice wins, false otherwise.

💡
Key insight: The array has an even length and odd total. This means Alice can always choose to take all even-indexed or all odd-indexed piles! She just picks whichever set has the larger sum — she always wins. But we'll still solve it with Minimax to learn the general technique.

03 — Intuition
🧠
Why Minimax + Memoization?

Think of it like a chess match — when it's your turn, you pick the maximum score you can get. When it's the opponent's turn, they'll try to minimize your future score, so from your perspective the outcome is the minimum.


The recursion models this perfectly:

  • Pick left (piles[i]): You gain that value, but then the opponent plays optimally from the remaining subarray. The opponent picks the best for themselves, leaving you the min of two branches.
  • Pick right (piles[j]): Same logic — you gain that value, opponent minimizes your remaining gain.
  • You take the max of both choices because you play optimally too!
  • Memoization with t[i][j]: Since many subproblems repeat, we cache results in a 2D array to avoid recomputation.
⚠️
Why min() inside and max() outside?
After you pick, the opponent picks next (they maximize for themselves = minimize for you). So from your perspective, you get the minimum of the two remaining options — then you choose whichever starting pick gives you the maximum overall.
04 — Approach
🗺️
Step-by-Step Approach

1. Define the recursive function solve(i, j)

It returns the maximum score the current player (Alice) can collect from the subarray piles[i..j].

2. Base cases

If i > j → no piles left → return 0.
If i == j → only one pile → return piles[i].

3. Explore both choices with memoization

Pick left: gain piles[i] + min(solve(i+2,j), solve(i+1,j-1))
Pick right: gain piles[j] + min(solve(i+1,j-1), solve(i,j-2))
Store the result in t[i][j] before returning.

4. Compare Alice's score to Bob's

If Alice > total − Alice, Alice wins!

06 — Methods & Functions
⚙️
Key Functions Explained
Function Purpose
solve(i, j, piles) Recursively finds the max score Alice can get from subarray piles[i..j]. Uses memoization table t[i][j].
stoneGame(piles) Driver function — computes total sum, calls solve() for Alice's best score, then checks if Alice > Bob.
memset(t, -1, ...) Initializes the memoization table with -1 to indicate uncomputed states.
min(a, b) Used to simulate the opponent's optimal play — they leave you the worst option.
max(a, b) Used by the current player to choose the best of two picks (left vs right).
07 — Patterns Used
🧩
Design Patterns
🎮 Minimax Game Theory
🔄 Recursion + Memoization
📦 Interval DP (i, j)
🧪 Optimal Substructure
✂️ Two-End Picking
  • Minimax: You maximize your gain; the opponent minimizes it. Classic two-player game pattern.
  • Memoization: The 2D table t[i][j] caches results to avoid exponential recomputation.
  • Interval DP (i, j): The subproblem is defined by a contiguous subarray from index i to j. This shrinks as picks happen.
  • Two-End Picking: Players can only pick from the left or right end — this constrains the search space elegantly.
  • Optimal Substructure: The optimal solution for solve(i,j) depends on optimal solutions of smaller subproblems.
08 — Full Code
C++ • solution.cpp 
// leetcode problem 877 Stone Game
// https://leetcode.com/problems/stone-game/
#include <iostream>
#include <vector>
#include <algorithm>
#include <cstring>
using namespace std;

class Solution {
public:
    int t[501][501];              // memoization table
    int solve(int i, int j, vector<int>& piles) {
        if(i > j) {                 // no piles left
            return 0;
        }
        if(i == j) {                // only one pile
            return piles[i];
        }
        if(t[i][j] != -1) {          // already computed
            return t[i][j];
        }
        // Pick left: piles[i], opponent plays optimally
        int take_i = piles[i] + min(solve(i+2,j,piles), solve(i+1,j-1,piles));
        // Pick right: piles[j], opponent plays optimally
        int take_j = piles[j] + min(solve(i+1,j-1,piles), solve(i,j-2,piles));

        return t[i][j] = max(take_i, take_j);   // best of both picks
    }

    bool stoneGame(vector<int>& piles) {
        int n = piles.size();
        int total = 0;
        for(int i = 0; i < n; i++) {
            total += piles[i];
        }
        memset(t, -1, sizeof(t));  // init memo table

        int Alice = solve(0, n-1, piles);
        int Bob = total - Alice;

        return Alice > Bob;           // Alice wins?
    }
};

int main() {
    Solution s;
    vector<int> piles = {5, 3, 4, 5};
    cout << s.stoneGame(piles) << endl;  // Output: 1 (true)
    return 0;
}

10 — Complexity Analysis
📊
Time & Space Complexity
Time
O(n²)
n² unique (i, j) subproblems.
Each solved once with memoization.
Space
O(n²)
2D memoization table t[n][n]
+ O(n) recursion stack.
🚀
Fun fact: For this specific problem, you can just return true; because Alice can always choose the parity (even/odd indexed piles) that gives her the larger sum. But the Minimax approach is the general technique that works for all game theory problems!
11 — Key Takeaways
✅
Remember These
  • Minimax = you maximize, opponent minimizes. Classic game theory.
  • The min() inside represents the opponent being smart — they'll pick the worse option for you.
  • Memoization with t[i][j] drops time from O(2ⁿ) to O(n²).
  • Subproblem is defined by an interval [i, j] — shrinks from both ends.
  • Alice's total is computed by solve(); Bob gets total − Alice.
  • For Stone Game specifically: Alice always wins (even/odd parity argument) — but the technique generalizes!
  • This pattern appears in many game theory problems: Predict the Winner, Coins in a Line, etc.
